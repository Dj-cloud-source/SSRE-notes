MySQL 里的层次、逻辑结构

* 库（database）
	* 表（tables）
		* 元数据





和 Linux 有点像

但 Linux 是命令行式，而 MySQL 是声明式，也就是说用 平常看得懂的英语来写命令，所以更加简单易懂

| MySQL       |               | Linux    |           |
| ----------- | ------------- | -------- | --------- |
| 库 database | show database | 目录     | ls -ll  / |
| 表 tables   | use tables    | 文件     | cd /mysql |
|             | show tables   | 切换路径 | ls        |



第一个重点是 SQL 语句



DDL、DCL、DML 都是数据控制语句，也就是所谓的 **增删改**。

这部分关系到后面的存储引擎、事务、事务锁、日志、备份、主从复制。



还有一个是 DQL ，也就是**数据查询语句** 。

数据查询语句，涉及一系列查询语法；以及让查询更快的 索引、B+ 树数据结构

毕竟，你懂的，只要涉及数据结构，就会想要更快，所以还得解决慢查询的问题





所谓事务，就是一系列 增删改 操作的集合。

而且事务之间，在操作数据时一般是隔离的，只有 commit 提交后才能看见“外面”。

事务回滚，你懂的，MySQL 记录了你的操作步骤，redo、undo，对吧。所以 MySQL 的机制决定了可以回滚。



日志

也是记录 数据操作步骤的东西。

日志这东西挺重要的。最主要的是 binlog 

通过日志，运维可以恢复数据。

当然，考虑到只用一台机器记录数据，肯定是不安全的，

所以引出了 主从复制。

就是 从库 接受 主库 发来的数据操作步骤，跟着照做，这样就能达到备份数据的效果。

然而，在主从复制的时候，中间件 PHP 绑定了主库的IP，这样其实会有隐患。

PHP 只认 IP 地址，但主库坏了，这个 IP 相当于用不了，那就直接寄了，

所以又引出了用来解决 IP 问题的高可用架构、vIP漂移
