## TCP/IP 协议与 三次握手 四次挥手 





先说 TCP/IP 协议

就像寄快递，通常需要这几样信息

* 本人是谁
* 对方是谁
* 你要寄什么
* 用哪家快递寄
* 对方收到后怎么确认



网络通信也一样，想访问一个网站，电脑也得知道：

* 要发给哪台服务器
* 发的内容是什么
* 对方怎么知道是发给它的
* 数据乱了怎么办
* 数据丢了怎么办



所以网络通信不是简单的收发，而是有套处理规则，这套规则就叫 **协议** 。



那什么是协议？协议可以理解为： *大家提前约定好的规则* 。

如果没有规则，那大家各说各的，就乱了，所以网络通信需要有协议



TCP/IP 是什么？

它也是一套网络通信协议

* IP 负责找到对方
* TCP 负责把数据 **可靠地** 传输数据



IP 负责定位和寻址，找到目标机器。这个就不多赘述。



TCP

光找到地址还不够，还要确保数据完整到人家手上

因为在发一段数据时，可能会遇到这些问题：

* 丢包（？）
* 顺序乱了
* 对方没收到

所以 TCP 就是为了解决这些问题的：**负责可靠传输** 



基于想要 “可靠的传输” 的宗旨，TCP建立了一个比较长但是安全的流程，来保证数据传输的可靠性，也就是：

三次握手，四次挥手

（握手是建立连接，挥手是断开连接）



---



所以 TCP 在在正式传输数据之前，先要建立连接，先相互确认一下。这个“建立连接”的过程，就叫：

 *三次握手* 

通俗理解：



第一次握手

Client 说：“喂，你在吗？我想和你通信。”



第二次握手

Server 说：“我在，我听到你了，你能听到我吗？”



第三次握手

Client 说：“我收到你的回复了。那我们正式开始说话吧。”



自此，连接建立完成，这就是三次握手。

一言以蔽之，就是 **在正式传输据前，双方先确认彼此通信正常** 。



> 为什么是三次，而不是两次？
>
> 如果只有两次：
>
> Client ：我想通信
>
> Server ：允许通信 
>
> 。
>
> 看起来好像够了，但其实不够，
>
> 因为服务器不知道 Client 到底有没有准备好
>
> 所以，双方都要确认， **彼此都没问题** 
>
> Client 必须第三次发送确认，“我收到了 Server 的回复”。
>
> 这样，双方才都放心，流程也符合 **可靠** 的宗旨。



---

然后就是传输据了

---



等传完了数据，就要断开连接，这个断开也有个流程，就叫：

四次挥手



通俗理解：

第一次挥手

Client ：“我话说完了，我不想发了。”



第二次挥手

Server ：“好，我知道你不想发了。但是你等我一下，我要检查，看一下我数据有没有发完。”



第三次挥手

Server ：“我也说完了，我也不发了。”



第四次挥手

Client ：“好，我知道了，那就真正挂电话了。”





> 为什么是四次？
>
> 因为网络通信是双向的，你可以发给我，我也可以发给你，两边是分开独立的
>
> 所以断开时，不能说拜拜就马上挂电话，留下没传完数据、一脸懵逼的对方。😂



小总结一下

TCP 连接的整个生命周期：

还没连接的”空闲“状态 → 建立连接 → 正常传输据 → 断开连接 → 完全结束











补充一些缩写的意思



* SYN ：synchronize 同步
	* 意思是：“我想建立连接”
* ACk ：acknowledgement 确认
	* 意思是：“我收到了”
* FIN ：Finish 结束
	* 意思是：“我发完了，先不发了，准备断开”





* TIME_WAIT ：等待时间状态

	* 第一次主动发出 FIN 的一方（不一定是客户端），通常会进入一个等待状态，”最后还要稍微等一下，确保最后那个 ACK 真正到达，避免旧连接残留问题。“

	


2025年8月9日 补充TCP与UDP的区别

TCP 负责可靠，数据完整
UDP 负责速度，低延迟


所以呢，不能单纯说 TCP 可靠，UDP 不可靠。
真正理解，要看**业务需求** 


一般在视频通话、实时音频和游戏操作中，大多数用的是 UDP 。

想象一下，
比如下载一个文件，文件内容一个都不能少吧。少一个，文件直接坏了，所以需要TCP。

但是视频通话，如果用的TCP，丢包的时候，就会感到卡了一下。
而UDP ，它不管那么多，新的包继续送。


这个丢包在人的耳朵感官上，只是“好像有杂音”，而不是“停住了”。




所以如何选择，是看哪种协议更符合业务目标。

## socket 套接字

和操作系统一样，socket 也把复杂的 TCP/IP 网络通信抽象成一套 API 接口

程序通过 socket 这套接口，让操作系统帮他们完成通信





另外还有个概念：

 port 端口

一台电脑上会同时运行很多程序，数据到了电脑上，操作系统怎么知道该把数据给谁呢？

靠的就是 端口 port

端口：找到电脑里的具体进程或服务



常见的 socket 类型

最常用的是 `AF_INET` ，意思是用 IPv4 网络地址

 ```python
 socket.AF_INET
 ```



还有表示 TCP 协议的

```python
socket.SOCK_STREAM
```



这两个通常组合在一起

```python
socket.socket(socket.AF_INET,socket.SOCK_STREAM)
```

> 表示创建一个 IPv4 + TCP 的 socket
