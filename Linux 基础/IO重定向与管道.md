# I/O重定向与管道



## 什么是重定向？

$默认情况下，程序的输入来自键盘（标准输入），输出显示在终端（标准输出），错误信息也显示在终端（标准错误）$

$而 ”输出重定向“则是$

> **输出重定向 = 把程序“本来要显示在屏幕上的东西”，改到别的地方去**

比如：

```text
ls
```

默认行为：

- 命令结果 → 显示在终端

如果你写成：

```text
ls > filelist.txt
```

结果变成：

- 命令结果 → 写入 `filelist.txt`

## 基础重定向



###  `>` ：覆盖输出

`command` ==`>`== `file` 

> 若文件已存在则**覆盖原有内容**（危险操作！）

```bash
date > date.txt 
cat date.txt
 
 date > date.txt 
 cat date.txt
```

### `>>` ：追加输出

（增加新的内容）

`command` ==`>>`== `file` 

```bash
date >> date1.txt
date >> date1.txt
cat date.txt
```



### `<`：输入重定向



将输入的来源，从键盘改为文件

（这里可以理解一点点所谓的 “ I/O ” ）



`command` ==`<`== `source_file`

## 文件描述符

接下来讲 文件描述符

### 引言

我们说**Linux 一切皆文件** ： **Linux 把各种资源统一抽象为“可以用文件描述符操作的对象“**



进程不直接操作设备、管道、网络等对象，而是统一通过 *文件描述符* 来访问它们。

Linux 中的程序通常不知道，也不关心，文件的格式和里面的内容。

程序只需要：

- open()
- read()
- write()
- close()

就能操作：

- 文件
- 设备
- 网络
- 管道
- 终端





### 文件描述符是什么？

​	file descriptor

> “进程内部用来标识一个对象的编号”



文件描述符表（fd table）

| fd   | 指向对象 | 含义                                                         |
| ---- | -------- | ------------------------------------------------------------ |
| 0    | stdin    | 输入                                                         |
| 1    | stdout   | 正确输出                                                     |
| 2    | stderr   | 错误输出                                                     |
| 3    | file.txt | 临时文件                                                     |
| 4    | socket   | [套接字]( 'Socket被称为“套接字”是因为它在网络通信中起到了类似于插座的作用，连接了不同的网络节点') |
| 5    | pipe     | 管道                                                         |



---



### 文件描述符 + 重定向

将 *重定向* 与 *文件描述符* 结合起来

> 程序的错误信息默认输出到终端，与普通显示混淆。若需单独捕获错误（如日志记录），可 文件描述符 +重定向 



```bash
touch file…
cd file
……
cd file 2> log.txt
cd file 2>> log.txt
cat log.txt
```





### 同时重定向

 ==`&>`== ：合并覆盖（兼用写法 `2>&1` ，`command > output.log 2>&1` 

 ==`&>>`== ：合并追加

## 管道



管道 `|` ：”连接命令的数据流”。虽然 *管道* 不算 *重定向* ，但它是处理 I/O 流的**核心工具**

**将前一个命令的结果传递给后一个命令处理**



命令 

 ==`command 1` `|` `command 2` `|` `command 3`==  



command 1 的结果 → command 2 → command 3



 `tee` 管道：就是处理命令的同时将结果打印到屏幕

 ==` command 1 | tee command 2 `==
