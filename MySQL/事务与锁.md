
# 事务
MySQL 事务，是指一组DML操作作为一个整体执行，要么全部执行成功，要么全部失败回滚

事务的四大特性：ACID
1. Atomicity 原子性
2. Consistency 一致性
3. Isolation 隔离性
4. Durability 持久性

（事务的学习和使用主要围绕四大特性）


事务使用

用`begin;` 开始一个事务
中间是DML 语句
结束事务 `commit;`  

```sql
begin;

update account set money = money - 100 where name = '张三';

commit;
```


如果“突然不想了”，可以回滚整个未提交事务

```sql
begin;

delete from user where user_id = 1 ;

rollback;

```


存档点
```sql
begin;

insert into products (product_name,price) values ('apple',100 );

savepoint my_savepoint;

update products set price=120 where product_name = 'apple';

rollback to savepoint my_savepoint;

commit; 
```

事务日志
事务依靠日志实现回滚和崩溃恢复
主要对应持久性和原子性

1. redo log ：记录数据页做了哪些修改，用于数据库崩溃后的恢复，保证持久性

2. undo log：记录修改前的数据，用于 rollback回滚，保证原子性


事务锁
主要对应隔离性


单个事务很简单
真正麻烦的是多个事务同事操作同一批数据，
这时就会出现并发问题：
1. 脏读：读到了别人还没提交的数据
2. 不可重复读：同一个事务里，两次读同一行数据，结果不一样（第二次读到别人commit同一行的数据）
3. 幻读：同一个事务里，两次按条件查询，结果集数量不一样（也是别人插入新行影响了查询）


隔离级别
MySQL可以用*隔离级别* 来解决上面的问题
1. 可读未提交
2. 可读以提交
3. 可重复读（默认）
4. 隔离串行化

从宽松到严格
读未提交 < 读已提交 < 可重复读 < 串行化



查看当前隔离级别
```sql
SELECT @@transaction_isolation;
```

修改隔离级别
```sql
SET SESSION TRANSACTION ISOLATION LEVEL SERIALIZABLE;
#READ UNCOMMITTED
#READ COMMITTED
#REPEATABLE READ
#SERIALIZABLE
```




MVCC 
MVCC 多版本并发控制

它解决的问题是：**当多个事务同时读写同一条数据时** ，MySQL 如何做到尽量不加“锁”，也能让`select` 到一致的数据。能让你稳定的**查** 

GPT-“简单理解：同一条数据被修改时，MySQL 不仅保存最新版本，还能通过 undo log 找到旧版本。不同事务根据自己的时间点，看到自己的数据版本”


MVCC靠什么实现？
1. 隐藏字段
	- InnoDB 内部会记录事务ID和旧版本指针
2. undo log 版本链
	- 保存数据的旧版本
3. Read view
	- 判断当前事务能看哪些版本


两种读
1. 快照读：普通 `select` ，读历史快照，依赖 MVCC
2. 当前读：`update` `delete`  `select …… for update`，读最新版本，通常加锁

隔离级别区别
可读已提交：每次快照读都生成新的 `read view` （普通 `select`）
可重复读：事务内第一次快照读生成 `read view` ，后续复用



## 锁



当多个事务同时修改同一批数据时，如何避免并发冲突？避免数据被乱改？
这就由此引出“锁”的概念



1. 表锁：锁住整张表。覆盖面大，管理简单，但并发能力差
2. 行锁：只锁住命中的行。覆盖面小，并发能力强。是 InnoDB 常用的锁方式


3. 共享锁（读锁）：多个事务一起读。但不能同时写
4. 排他锁（写锁）：一个事务加了排他锁后，其他事务不能再改这行数据（`update` `delete` 通常加排他锁）

5. 间隙锁：锁住一个范围，主要是为了防止其他事务在这个范围内插入新数据，从而减少幻读问题

6. 死锁：两个事务相互等待对方释放锁，导致谁也执行不下去
		解决死锁的方法
	1. 多个事务尽量按相同顺序访问数据
	2. 事务尽量短，别长时间占着锁
	3. SQL条件尽量命中索引，避免锁范围过大
	4. 发现死锁后，MySQL会回滚其中一个事务


最后
InnoDB 的行锁是加在索引上的

条件命中索引，锁得更精准
条件不走索引，可能会锁住很多行
