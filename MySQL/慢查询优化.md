## 慢查询优化 

如果SQL查询慢了，会让用户感觉到“卡”，并拖慢借口、占用数据库资源，严重时会引发锁等待，拖慢整个系统，影响实际业务。


慢查询优化，就是找出慢SQL，然后让MySQL少扫数据、少排序、少回表、少等待。
```markdown
发现慢SQL——》看explain ——〉判断索引、扫描行数、排序、临时表——》改索引、改
SQL、改表结构——〉再explain
```




“慢”通常需要一个阈值判断，比如超过1/2/10秒，
这样的SQL，就会被记录到 `slow query log` 慢查询日志里



查看慢查询配置
```sql
#是否开启慢查询日志
mysql> show variables like 'slow%log';

+----------------+-------+

| Variable_name  | Value |

+----------------+-------+

| slow_query_log | OFF   |

+----------------+-------+

1 row in set (0.02 sec)

  
#超过多少秒算慢查询
mysql> show variables like 'long%time';
+-----------------+-----------+

| Variable_name   | Value     |

+-----------------+-----------+

| long_query_time | 10.000000 |

+-----------------+-----------+

1 row in set (0.00 sec)

  
#慢查询日志文件位置
mysql> show variables like 'slow%log%file';

+---------------------+------------------------------------+

| Variable_name       | Value                              |

+---------------------+------------------------------------+

| slow_query_log_file | /var/lib/mysql/Rocky-test-slow.log |

+---------------------+------------------------------------+

1 row in set (0.01 sec)
```

永久开启慢查询日志
```bash
vim /etc/my.cnf

#加入
slow_query_log=ON
slow_query_log_file=/var/lib/mysql/mysql-slow.log
long_query_time=1



#然后重启
systemctl restart mysqld
```


常见优化套路
1. `where` 后的 高频高区分度条件字段 加索引
2. `join` 后的连接字段加索引
3. 不要 `select *` 
4. 避免索引字段上套函数
5. 避免左模糊 如    ` like  '%王'` 
6. `order by` 字段考虑联合索引
7. `group by` 字段考虑建立索引

8. 改表结构：字段类型、冗余字段、分表



改业务逻辑
 1. `limit` 深分页优化
2. 大事务、锁也会造成慢查询
3. 缓存、异步、预计算
