## 慢查询优化 

```markdowm
发现慢SQL——》看explain ——〉判断索引、扫描行数、排序、临时表——》改索引、改
SQL、改表结构——〉再explain
```

慢查询优化就是找出慢SQL，然后让MySQL少扫数据、少排序、少回表、少等待。


“慢”通常用一个阈值判断，比如1/2/10秒的SQL，
这种SQL会被记录到 `slow query log` 慢查询日志里



查看慢查询配置
```sql
#是否开启慢查询日志
mysql> show variables like 'slow%log';

+----------------+-------+

| Variable_name  | Value |

+----------------+-------+

| slow_query_log | OFF   |

+----------------+-------+

1 row in set (0.02 sec)

  
#超过多少秒算慢查询
mysql> show variables like 'long%time';
+-----------------+-----------+

| Variable_name   | Value     |

+-----------------+-----------+

| long_query_time | 10.000000 |

+-----------------+-----------+

1 row in set (0.00 sec)

  
#慢查询日志文件位置
mysql> show variables like 'slow%log%file';

+---------------------+------------------------------------+

| Variable_name       | Value                              |

+---------------------+------------------------------------+

| slow_query_log_file | /var/lib/mysql/Rocky-test-slow.log |

+---------------------+------------------------------------+

1 row in set (0.01 sec)
```

永久开启慢查询日志
```bash
vim /etc/my.cnf

#加入
slow_query_log=ON
slow_query_log_file=/var/lib/mysql/mysql-slow.log
long_query_time=1
log_queries_not_using_indexes=ON


#然后重启
systemctl restart mysqld
```


常见优化套路
1. `where` 后的 条件字段 加索引
2. `join` 后的连接字段加索引
3. 不要 `select *` 
4. 避免索引字段上套函数
5. 避免左模糊 如    ` like  '%王'` 
6. `order by` 字段考虑联合索引
7. `group by` 字段考虑建立索引
8. `limit` 深分页优化（跳表？）
9. 大事务、锁也会造成慢查询
