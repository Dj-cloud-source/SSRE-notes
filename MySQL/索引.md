
## 前言
### 索引作用
MySQL索引，是表里数据的目录。能让数据库少扫数据、更快找到目标行
没有索引，就会全表扫描，当数据量很大时，查询会很慢。

MySQL表就像一本很厚的书，索引的作用是提前建一份目录，这样MySQL就不用把整张表看一遍，而是先查目录，再找数据

### 底层B+树
InnoDB 中最常见的索引结构是B+树
“空间换时间”
因为B+树适合范围查询、排序、磁盘读取![[Pasted image 20260719095924.png]]


Redis 键值对和MySQL索引
Redis kv “已经知道门牌号，直接取”
MySQL 索引 “不知道数据在哪，先查目录、再定位数据”


### 主键索引

主键索引最重要，在InnoDB里，主键索引通常是数据本身的组织方式。数据按主键排好，挂在 B+ 树上。
主键索引的叶子节点存整行数据；普通索引的叶子节点通常存主键值

```sql
id int primary key
```


普通索引

联合索引
最左前缀原则


回表（不理解）：通过普通索引查到primary key 后，还需要再拿这个主键去主键索引里查整行数据
比如普通索引 idx_name(name):
1. 先在idx_name 里找到 name='张三' 对应的 id
2. 再用 id 去主键索引里找到完整行数据（这一步就叫回表）
覆盖索引



索引不是越多越好
修改数据时，MySQL不仅要改表数据，还要维护索引，索引越多，写入和更新成本越高


哪些应该建立索引？【建立索引的原则（规范）】

**高频查询的大表字段** 
经常的：
`where` 后面经常查询的字段
`join`  关联的字段
`order by` 
`group by`

区分度高的字段：身份证、手机号、订单号


慢查询优化？
实际建索引策略





## 索引命令

查看已有索引
```sql
show index from student;
```

创建普通索引
```sql
alter table  student add index idx_name(name);
# idx_  是业务常用命名习惯
create index idx_sex on student(s_sex);
```

修改索引名称
```sql
alter table student rename index idx_name to index_name ;
```

删除索引
```sql
alter table student drop key idx_sex;
```


> 主键索引在创建表是就已经添加了。主键具有唯一性，每张表只能有一个主键


添加唯一索引
给手机邮箱添加唯一索引
```sql
alter table student add s_phone varchar(20);

alter table student add unique index idx_phone(s_phone);
```



联合索引

```sql
alter table student add index idx_gam(s_phone,s_name);
```

>最左前缀原则：查询条件必须从联合索引的最左侧列开始匹配，不能跳过中间的列。





## explain

### explain 是看SQL怎么跑的，看MySQL准备怎么执行一条SQL的。
“不是查数据本身，而是：
MySQL准备查哪张表
有没有用索引
用了哪个索引
大概要扫多少行
有没有全表扫描
有没有排序、临时表“

**explain 是让你判断SQL语句的好坏的**



### 用法：
在SQL语句前面加 `explain` 

```sql
mysql> select name,countrycode from city where id = 1;

+-------+-------------+

| name  | countrycode |

+-------+-------------+

| Kabul | AFG         |

+-------+-------------+

1 row in set (0.00 sec)


mysql> explain select name,countrycode from city where id = 1;

+----+-------------+-------+------------+-------+---------------+---------+---------+-------+------+----------+-------+

| id | select_type | table | partitions | type  | possible_keys | key     | key_len | ref   | rows | filtered | Extra |

+----+-------------+-------+------------+-------+---------------+---------+---------+-------+------+----------+-------+

|  1 | SIMPLE      | city  | NULL       | const | PRIMARY       | PRIMARY | 4       | const |    1 |   100.00 | NULL  |

+----+-------------+-------+------------+-------+---------------+---------+---------+-------+------+----------+-------+

1 row in set, 1 warning (0.00 sec)
```



possible_keys 理论上可能用哪个索引

key 实际用了哪个索引


type 查询效率等级
`system > const > eq_ref > ref > range > index > ALL` 
主键或唯一索引等值查询，通常是 `const` 
通过普通索引等值查询，可能是 `ref` 。因为普通索引可能重复，所以MySQL可能查出多行。
`range` 范围查询
后面的就不太理想了


rows 预计要扫多少行。
rows 很有参考价值，数值越小，一般越好。


Extra  
`using where` 说明用 `where` 条件过滤，常见，不一定有问题。
`using index` 这是比较好的情况，表示可能用了覆盖索引。
`using filesort` 排序 `using temporary` 临时表     要警惕





看一条SQL，如果出现
```markdown
type = ALL
key = NULL
rows 很大
Extra = Using filesort
```
说明这条SQL需要优化
