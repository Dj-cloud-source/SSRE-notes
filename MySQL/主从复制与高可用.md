
## 逻辑纲要

为什么需要主从？
老生常谈：
1. 数据冗余
2. 读写分离
3. 故障切换基础
4. 备份与报表隔离



主从复制原理
1. 主库写binlog
2. 从库拉取binlog
3. 从库写relay log
4. 从库重放日志

核心线程
1. 主库 binlog dump thread
2. 从库 I/O thread
3. 从库 SQL thread

复制定位方式
- 文件名+Position
- GTID


主从搭建
1. 配置主库
2. 配置从库
3. 创建复制用户
4. 导入初试数据
5. 建立复制关系


状态检查
1. `show replica status\G`
2. `replica_io_running` 
3. `replica_sql_running`
4. `seconds_behind_source`



## 主从复制
主从复制的大致流程：
主库负责增删改数据，并把修改记录到 binlog；
从库 Sever I/O Thread 拉取主库的binlog，
写入自己的relay log，
然后重放这些日志，让从库数据和主库保持一致。




读写分离

主从延迟：主从复制通常是异步的


## 操作示例


编辑主库配置文件
```bash
vim /etc/my.cnf

[mysqld]
server_id=1
log_bin=mysql-bin
```


```bash
#先保证数据一致
#主库导出数据，保证数据一致性
mysqldump -uroot -p123 -A -R --triggers --master-data=2 --single-transaction > /tmp/full.sql

head -50 /tmp/full.sql | grep -i "CHANGE MASTER"

scp /tmp/full.sql  root@10.1.1.1:/tmp

#从库导入数据
mysql  -uroot  -p123456
mysql>source  /tmp/full.sql

```


创建主从复制用户rep
```bash
mysql -uroot -p123456
```
```sql
mysql>grant replication slave on *.* to rep@'10.1.1.%' identified by '123456';
```

编辑从库配置文件
```bash
vim /etc/my.cnf

[mysqld]
server_id=5
log_bin=mysql-bin

#重启
/etc/init.d/mysqld  restart
#记录主库binlog及位置点
mysql>show master status;
```
```bash
mysql -uroot  -p123456
```
```sql

mysql> change master to
-> master_host='10.0.0.51',
-> master_user='rep',
-> master_password='123456',
-> master_log_file='mysql-bin.000004',
-> master_log_pos=120;

#head -50 /tmp/full.sql内的master_log_file与master_log_pos

#执行change master to 语句

mysql>start slave
mysql>show  slave status\G


#看到Slave_IO_Running: Yes    Slave_SQL_Running: Yes表示运行成功
#从数据库：/application/mysql/data目录下出现master.info文件，记录了同步的索引号
#测试方法：在主里面库建表插入内容，从里面可以看到主新增的内容表示同步成功
```
