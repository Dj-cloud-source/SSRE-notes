
如果不把配置文件、数据库地址、密钥、Token直接写死在镜像和Pod yaml 里，那你可以了解一下配置存储

假如应用镜像里写死配置环境，测试环境和生产环境不一样，每次改都要重新构建，很麻烦，
所以k8s的做法是镜像只保存应用程序，配置另外分离，pod启动时才把配置注入容器里


- ConfigMap：保存普通配置
- Secret：保存敏感配置

更多时候是两个一起使用
```yml
envFrom:
  - configMapRef:
      name: app-config

  - secretRef:
      name: mysql-secret
```


## configmap

pod使用配置：
1. 注入成环境变量（不会自动更新）
2. 挂载成配置文件（可以同步更新）

### 用yaml文件创建configmap

```yml
#configmap.yaml

apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  name: admin
  password: "123456"
  APP_ENV: production
  LOG_LEVEL: info
  DB_HOST: mysql-service
  DB_PORT: "3306"
  
```
> configmap 中的值通常按字符串处理，所以端口建议加引号

```bash
kubectl apply  -f  configmap.yaml

#查看
kubectl get cm
```



### 注入环境变量的pod

```yml
#pod77.yaml

apiVersion: v1
kind: Pod
metadata:
  name: config-demo
spec:
  containers:
    - name: busybox
      image: busybox:1.38
      command:
        - /bin/sh
        - -c
        - |
          env
          sleep 3600

      envFrom:
        - configMapRef:
            name: app-config
```


```bash

kubectl apply  -f  pod77.yaml
kubectl rollout restart deployment app_name

#查看一下环境变量
kubectl  logs config-demo
```



#### 只引用一个配置的写法

```yml
#

apiVersion: v1
kind: Pod
metadata:
  name: config-demo
spec:
  containers:
    - name: busybox
      image: busybox:1.38
      command:
        - /bin/sh
        - -c
        - |
          env
          sleep 3600



      env:
        - name: DATABASE_HOST
          valueFrom:
            configMapKeyRef:
              name: app-config
              key: DB_HOST	              

#ConfigMap中的 DB_HOST
#       ↓
#容器环境变量 DATABASE_HOST



```
















### 用挂载文件的形式，挂载configmap


```yml
#nginx-config.yaml

apiVersion: v1
kind: ConfigMap
metadata:
  name: nginx-config
data:
  default.conf: |
    server {
        listen 80;

        location / {
            return 200 "hello configmap\n";
        }
    }
    
    
```

```yml

#nginx-pod.yaml

apiVersion: v1
kind: Pod
metadata:
  name: nginx-config-demo
spec:
  containers:
    - name: nginx
      image: nginx:1.27
      volumeMounts:
        - name: nginx-config
          mountPath: /etc/nginx/conf.d
  volumes:
    - name: nginx-config
      configMap:
        name: nginx-config
        
        
```
>镜像老是拉取失败……
```
# 挂载关系

ConfigMap
default.conf
    ↓
Volume
    ↓
容器目录
/etc/nginx/conf.d/default.conf
```

```bash
kubectl apply  -f  nginx-config.yaml
kubectl apply  -f  nginx-pod.yaml

```





## Secret

Secret 也有环境变量和文件挂载的使用方式，所以和上面差不多。

我们这里纠正一个误区。用base64不是为了安全，而是为了解决各种数据在传输和存储时遇到的格式和字符问题。




yaml示例
```yml
#mysql-secret.yaml

apiVersion: v1
kind: Secret
metadata:
  name: mysql-secret
type: Opaque
stringData:
  MYSQL_USER: root
  MYSQL_PASSWORD: "123456"
  
```


```yml
#secret-demo.yaml

apiVersion: v1
kind: Pod
metadata:
  name: secret-demo
spec:
  containers:
    - name: busybox
      image: busybox:1.38
      command:
        - /bin/sh
        - -c
        - |
          test -n "$MYSQL_USER" && echo "MYSQL_USER loaded" 
          test -n "$MYSQL_PASSWORD" && echo "MYSQL_PASSWORD loaded"
          sleep 3600

      envFrom:
        - secretRef:
            name: mysql-secret
            
```

```bash
kubectl apply -f mysql-secret.yaml
kubectl apply  -f  secret-demo.yaml

kubectl logs secret-demo

```
